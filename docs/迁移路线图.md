# rbatis-plus 全量迁移路线图

> 版本：v1.0（2026-07-28）｜基线：baomidou/mybatis-plus **v3.5.17** + mybatis-plus-enhance **2.0.x** + mybatis-3 **3.6.0-SNAPSHOT** + rbatis-wrapper **0.1.1**
> 仓库：`workspace-github-easy-4-rust/rbatis-plus` @ dev ｜ 本文档随代码同步维护，每阶段完成时更新

---

## 一、总目标

以 baomidou/mybatis-plus 为主蓝本、mybatis-plus-enhance 作为企业增强、mybatis-3 作为执行底层、rbatis-wrapper 已被吸收为向后兼容示例为目标，**完全迁移**为 rbatis-plus Rust workspace。

| crate | 对应 Java 模块 | 当前状态 |
|---|---|---|
| **rbatis-plus-core** | mybatis-plus-core（含 mybatis-plus-annotation 内的 `@TableName` 等结构体语义、annotation 部分 process-macro 化） | 🚧 进行中（基础已落，部分字段补全中） |
| **rbatis-plus-macros** | mybatis-plus-annotation（过程宏化） | 🚧 已落 1 文件，待拆 16 个 sub-mod |
| **rbatis-plus-extension** | mybatis-plus-extension（含 mybatis-plus-jsqlparser 内置 inner） | 🚧 6 inner 已落（MVP），增强层 8 inner 待补 |
| **rbatis-plus-sqlparser** | mybatis-plus-jsqlparser（sqlparser 替代 jsqlparser） | ✅ 已落 3 dialect |
| **rbatis-plus-vernal** | mybatis-plus-spring（Vernal 替代 Spring） | ✅ 已落 axum_integration + config + state |
| **rbatis-plus-generator** | mybatis-plus-generator（含 tera/handlebars/askama/maud 4 引擎） | 🚧 已落 tera 引擎，3 引擎待补 |

**硬性规范**（与父会话约定一致）：

1. 目录/文件名 snake_case；类型 PascalCase；方法 snake_case；参数命名与 Java 一致
2. Java 子包 → Rust 同名子目录；多层嵌套（如 `io/checksum/crc16/`）只要求最后一级完全对齐
3. 注释从 Java 复制并中文化，标注对应 Java 类/方法行号
4. jackson → serde；Spring Boot → axum；Quarkus → actix；Spring 容器 → vernal；JNDI → vernal Provider
5. **一文件一对象**；禁止 lib.rs / mod.rs（除 `pub mod` 之外）/ compat.rs 堆放对象
6. annotation → 独立 proc-macro crate（rbatis-plus-macros）
7. 模板引擎速记：Tera ≈ FreeMarker（功能型）、Handlebars ≈ Velocity（克制型）、Askama ≈ 编译期 JSP/Thymeleaf、maud ≈ Twirl/JSX
8. **完全复用上游 rbatis 主接口**：`rbatis::plugin::Intercept` / `rbatis::plugin::cache::CacheStore` / `rbatis::plugin::cache::CacheIntercept` / `rbatis::plugin::transaction::TransactionListener` 等，重导出而非重写
9. 功能语义对齐；实现方式 Rust 化
10. **不动手发 PR 到 rbatis / mybatis-plus / mybatis-plus-enhance 上游**

## 六、工程规范与流程保障（全阶段强制）

### 测试门槛
- 每阶段：既有测试必须全绿；新增语义必须带测试
- `cargo check --workspace --all-features` 通过、`cargo doc --no-deps` 通过
- 提交前必跑：`cargo test --workspace`

### 推送流程（强制执行）
1. 推送内容**必须从磁盘读取**，禁止凭记忆内联
2. 每批推送后强制 `git blob SHA` 校验：本地 `sha1("blob "+len+\0+bytes)` vs 远端回读，不匹配立即重推
3. 全部推送后克隆 dev 整库 `diff -r`，exit 0 才算完成
4. Cargo.lock 不推（库项目惯例）；`.codegraph/` 不入库

### 严格禁止
- ❌ 在 $HOME 建 git worktree（沙箱周期清空 $HOME 已摧毁过 4 个并行 worktree）
- ❌ compat.rs / 集中式转发；每个 rs 文件必须对应一个 Java 对象
- ❌ 动 PR 到 rbatis / mybatis-plus / mybatis-plus-enhance / rbatis-wrapper 上游
- ❌ 在单文件内塞入多对象 / 用 wildcard re-export 逃避对象级审计

### 方法级审计脚本
- 仿照 `liteflow-rust/scripts/audit_java_method_parity.mjs`，创建 `rbatis-plus/scripts/audit_java_method_parity.mjs` 读两侧 CodeGraph，把 Java 公共方法映射为 snake_case 后在 Rust 目标文件找 `pub` 函数
- 对象级 %、方法级 % 每 iter 末更新到 `对象级对照表.md` 顶部统计
- **"304/304 文件存在 = 完成"是反结论**，必须以方法级作为完成度依据

### 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| mybatis-plus v3.5.17 较复杂，304 类可能估多估少 | iter 完成度 | S0 末做完整 304 类盘点，写入 `对象级对照表.md` |
| vernal / axum / actix 差异 | iter8 阻塞 | 阶段开始前做可用性 spike |
| testcontainers-rs 网络/沙箱限制 | iter5 集成 | 提供 in-memory fallback |
